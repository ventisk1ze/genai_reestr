# Реестр задач ЦК GenAI — правила проекта (читают все агенты)

## Что это
Веб-сервис реестра задач ЦК GenAI по регламенту «Процесс управления задачами ЦК GenAI»: реестр, доска, доклады, база знаний, письма по шаблонам, ИИ-помощник тимлида («лава-болл»). Работает в контейнере DataLab Pro (JupyterHub): владелец запускает сервер (`start.sh`, порт 39246), коллеги подключаются через `connect.sh`, браузер открывает его через jupyter-server-proxy. Подробности — README.md.

Разработка идёт на Mac пользователя, продакшн — DataLab Pro. Из DataLab на Mac нет ни Greenplum, ни шлюза моделей, ни GigaCode, ни хостов `jlab-<табельный>`: всё это в тестах подменяется (см. «Тестирование»).

## Состав
- `app.py` — точка входа (её зовут start.sh, connect.sh, команды GigaCode и тесты); код — в пакете `registry/`
- `registry/` — бэкенд на FastAPI, послойно: `config`/`errors`/`util`/`runtime` → `org`/`sessions`/`auth` → `store/` (json, sqlite, gp) → `tasks`/`settings`/`cards`/`kb` (база знаний) → `ai/` (скиллы, файлы, шлюз модели) → `bb/` (MCP-клиент Bitbucket: выгрузка T-010 и БЗ T-012) → `api/` (роуты, маппинг ошибок) → `server`/`main`; `proxy.py` и `cli.py` — сторона сотрудника на stdlib
- `templates/index.html` + `static/` — интерфейс без сборки: каркас (Jinja2) и ES-модули `static/js/`, стили `static/css/`
- `start.sh`, `connect.sh` — запуск владельцем и подключение коллег
- `skills/<имя>/SKILL.md` — скиллы ассистента, общие для веба и GigaCode
- `tests/` — тесты; `docs/backlog.md` — бэклог и журнал решений

## Жёсткие правила — нарушение означает, что задача не принята
1. **Логины, пароли, токены нигде не хранятся**: ни в файлах, ни в git-конфиге, ни в окружении процесса сервера (оно видно в `/proc/<pid>/environ`). Пользователь вводит их при каждом запуске; в процесс — только через stdin. Единственное исключение (решение пользователя, T-002): PIN сотрудников хранится только как хеш с солью (PBKDF2), сам PIN — нигде; хеши никогда не отдаются клиенту. Админский PIN не хранится вовсе — вводится при запуске `start.sh`. Идентификатор сессии (не PIN) может лежать в sessionStorage вкладки — решение пользователя, T-005; в localStorage — никогда.
2. **Без новых зависимостей — кроме принятых решением пользователя (рефакторинг на FastAPI).** Серверу владельца нужны `fastapi`, `uvicorn`, `jinja2` (`requirements.txt`; для GP — ещё `asyncpg`, ленивый импорт). Всё остальное — стандартная библиотека; сторона сотрудника (прокси, команды GigaCode, выгрузка в BB) — только стандартная библиотека, fastapi ей не нужна. Фронтенд — без CDN и без сборки (Jinja2-шаблон + ES-модули). Нужна ещё зависимость — остановись и спроси пользователя через тимлида.
3. **Никаких реальных данных**: ФИО, почта, задачи в тестах и примерах — выдуманные. Не читать `registry.env` и `data/` пользователя.
4. **Совместимость с DataLab Pro**: порты команды 39235–39246; адрес страницы может быть без слеша на конце; пути API относительные (`BASE`); файлы приходят через Windows (CRLF, cp1251) — `start.sh` это чинит, не ломать.
5. **Контракт API** (`/api/*`) используют фронтенд и команды GigaCode: меняешь — обнови обоих и README.
6. **Тексты интерфейса — по-русски**; термины регламента (статусы, этапы, темы писем) не менять без решения пользователя.
7. **Ассистент**: GigaCode из веба — только `--approval-mode default|plan`, `auto-edit` запрещён.

## Как проверять
- Ворота качества (их же запускает хук при закрытии задачи): `bash .claude/hooks/quality-gate.sh < /dev/null`
- Тесты: `python3 -m unittest discover -s tests -v`. Хук гоняет только `tests/test_*.py`; тесты к ещё не реализованной фиче называй `tests/wip_*.py`, после реализации — переименуй в `test_*.py`.
- Ручной запуск: `python3 app.py --local --no-browser --port 39299` (реестр — в `./data`, он в .gitignore), интерфейс — http://localhost:39299/

## Тестирование без DataLab
- Greenplum → `REG_STORAGE=sqlite` или локальный PostgreSQL с `REG_PG_PLAIN=1` (если установлен)
- Шлюз модели → мок HTTP-сервер на localhost, адрес в `GIGACHAT_API_URL`
- GigaCode → фейковый скрипт `gigacode` во временной папке, первой в `PATH`
- Хост коллеги `jlab-<табельный>` → `127.0.0.1:<порт>`
- Что проверить локально нельзя — явно перечислить в отчёте как «проверить на DataLab»

## Git
- `main` — только то, что принял пользователь. Работа — в ветках `feature/<id>-<кратко>`.
- Коммитит тимлид после ревью; сообщения — по-русски, кратко, с ID задачи: `T-003: письмо по шаблонам`.
- `git push` и слияние в `main` — только после явного «ок» пользователя.

## Уроки — грабли, на которые уже наступали
- Шар ассистента пропадал во время ответа: его класс состояния совпал с `.busy` заставки (`display:none`). Новые CSS-классы проверяй на конфликт имён (`grep`).
- Анимации нельзя глушить по `prefers-reduced-motion`: в VDI это включено, пользователь видит мёртвый интерфейс.
- Адрес `…/proxy/39246` без слеша ломал все запросы: `BASE` должен добавлять слеш. То же — для файлов каркаса: стили и `main.js` в шаблоне — только относительные пути (`static/…`), абсолютные `/static/…` уходят мимо jupyter-server-proxy; адрес без слеша чинит скрипт в каркасе до загрузки модуля.
- Кириллица в HTTP-заголовке не проходит: `X-User` — `encodeURIComponent` / `unquote`.
- Пароль через переменные окружения виден в `/proc/<pid>/environ` — передавать через stdin.
- GP6 не знает `ON CONFLICT`; у таблиц — `DISTRIBUTED BY`, совместимый с первичным ключом.
- `pkill -f <шаблон>` в тестах убивает собственную оболочку — останавливать процессы по PID.
- Баг сначала воспроизводят (скрипт, браузерный тест), потом чинят; «не воспроизводится у меня» — не ответ.
